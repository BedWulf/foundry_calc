# Windows: сборка и запуск (новый ПК)

**Рекомендуется:** скачать готовый архив `LiteynyiTsehPRO-Windows-x64` из GitHub **Actions** → **Build Windows EXE (PySide6)** → последний успешный запуск → **Artifacts**. Распаковать **всю папку**, запустить `LiteynyiTsehPRO.exe`. На целевом Windows 10/11 x64 Python не требуется.

Для автоматической сборки на GitHub: вкладка **Actions** → **Build Windows EXE (PySide6)** → **Run workflow**, ветка `engineering-audit-batch-planning-20261028`. Если GitHub Actions отключены, их нужно включить в настройках репозитория. Артефакт доступен после **успешного** задания; наличие workflow ещё не означает, что EXE успешно собран.

Для самостоятельной сборки на новом Windows 10/11 x64: распакуйте исходники, дважды запустите `build_windows.bat`. Потребуется доступ к интернету. Скрипт найдёт Python 3.12 x64 либо предложит/попробует поставить его через `winget`, создаст локальное виртуальное окружение `.venv`, установит PySide6/openpyxl/python-docx/pytest/PyInstaller, проверит тесты, затем соберёт *onedir*-пакет `dist\LiteynyiTsehPRO\`.

Если Python отсутствует и `winget` недоступен, установите Python **3.12 x64** с python.org, затем перезапустите батник. Если антивирус блокирует сборку, сначала проверьте происхождение скрипта и журнал защиты; не отключайте защиту системы ради сборки.

Папка `dist\LiteynyiTsehPRO` переносится **целиком**, вместе с внутренними DLL/Qt-библиотеками. EXE нельзя переносить отдельно. Данные пользователя записываются в `%APPDATA%\LiteynyiTsehPRO`, а не внутрь приложения, поэтому программа может работать из папки `Program Files` без прав администратора.

Важно: PyInstaller *упаковывает*, но не компилирует расчётный Python в нативный C++; формирует автономный набор исполняемых файлов для той же ОС и архитектуры. Linux-сборка не создаёт Windows EXE. Разработка и проверка сборки на чистой Windows остаются обязательными перед выпуском производственной версии. Даже успешно собранный EXE не является подтверждением инженерной правильности расчётов.


## Примечание о проверке EXE в CI
Автоматическая проверка внутри Windows runner выполняет запуск упакованного `LiteynyiTsehPRO.exe` в тестовом режиме и создание всего графического интерфейса **без отображения окна** (на безэкранном сервере). Это проверяет упаковку Python, DLL/Qt и совместимость импортов. Проверка фактического открытия окна, корректного сохранения настроек и экспорта на чистой Windows 10/11 должна выполняться вручную на рабочем компьютере. Артефакт без статуса `success` не следует использовать как выпускной.

Руководство пользователя встроено в приложение: пункт бокового меню **«❓ Руководство»**, доступно без интернета. Отдельный Markdown-файл: `docs/USER_MANUAL.md`. Сборщик включает папку docs в Windows-пакет.

Проверка упакованного EXE в CI выполняет загрузку Qt и проверку наличия основных ресурсов и руководства; **не** является тестом фактического открытия главного окна на пользовательском рабочем столе. Создание окна отдельно проверяется в исходном Python под Windows runner.
