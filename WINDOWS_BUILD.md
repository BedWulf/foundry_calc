# Windows: сборка LiteynyiTsehPRO.exe и решение ошибки длинных путей

## 1. Самый простой запуск на новом Windows 10/11 x64

Если в GitHub Actions уже есть успешная сборка: **Actions** → **Build Windows EXE (PySide6)** → успешный запуск для ветки `engineering-audit-batch-planning-20261028` → **Artifacts** → `LiteynyiTsehPRO-Windows-x64`.

Распакуйте **всю папку** приложения, затем запустите `LiteynyiTsehPRO.exe`. Python на компьютере, где приложение запускается, не нужен. Не копируйте один лишь файл `.exe`: библиотеки Qt поставляются рядом с ним.

## 2. Сборка EXE из исходников

1. Установите Windows Python **3.12 x64** (если ещё нет) и получите доступ к интернету для установки зависимостей.
2. Распакуйте проект из рабочей ветки. Запустите **обновлённый** файл `build_windows.bat`. На Windows 10/11 не требуется запускать его от имени администратора.
3. Скрипт создаёт виртуальное окружение **не в папке проекта**, а в коротком временном каталоге `%TEMP%\FPRO\venv`, устанавливает библиотеки, проверяет Python-синтаксис и тесты, собирает приложение PyInstaller и создаёт переносимый архив.

Успешный результат:
- `LiteynyiTsehPRO-Windows-x64.zip` **рядом со скриптом** — удобно переносить на другой ПК;
- папка с собранным приложением `%TEMP%\FPRO\dist\LiteynyiTsehPRO` — можно запустить `LiteynyiTsehPRO.exe` прямо из неё.

Для запуска готовой сборки Python на целевом компьютере не требуется.

## 3. Ошибка установки PySide6: Windows Long Paths / [Errno 2]

Симптом:

```text
[PySide6_Essentials] ERROR: Could not install packages due to an OSError:
[Errno 2] No such file or directory: ...\PySide6\qml\Qt\labs\assetdownloader\...
HINT: Windows Long Path support...
```

**Причина:** глубоко распакованная папка проекта и `venv` внутри неё дают слишком длинный путь к Qt-файлам. Это ошибка **установки библиотеки**, а не компиляции расчётов.

**Вариант A (рекомендуется):** скачайте новый `build_windows.bat` из GitHub и замените старый файл рядом с исходниками. Он теперь использует короткий каталог временной сборки, даже если проект расположен глубоко на диске F:. Старую частично установленную папку `.venv` внутри проекта можно удалить: новый скрипт её не использует. Рабочие файлы проекта не удаляйте.

**Вариант B (если используете старый скрипт):** перенесите исходники в очень короткий путь, например `F:\Foundry`, удалите **только** неудачную `.venv` и снова запустите `build_windows.bat`.

**Вариант C (если и короткий %TEMP% не помогает):** в обычной **Командной строке (cmd.exe)** выполните из папки проекта:

```bat
set "FOUNDRY_BUILD_HOME=F:\FPRO"
call build_windows.bat
```

Это создаст `F:\FPRO\venv` и `F:\FPRO\dist`. Для повторного запуска сначала закройте программы, использующие это окружение. Если установка была прервана и файлы повреждены, можно удалить **только** `F:\FPRO\venv` и запустить сборку снова.

**Альтернатива с изменением Windows:** администратор может включить `Enable Win32 long paths` / параметр реестра `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled=1`, после чего некоторым программам потребуется перезапуск или перезагрузка. Это системная настройка, она не нужна, если короткий путь уже устранил проблему. Не меняйте реестр ради первой попытки. Документация Python: https://docs.python.org/3.12/using/windows.html#removing-the-max-path-limitation

## 4. Исправление аварии при запуске: `core/melting.py` не найден

Сообщение:

```text
Unhandled exception in script
FileNotFoundError: Легаси-модуль не найден:
...\\LiteynyiTsehPRO\\_internal\\core\\melting.py
```

Это **не проблема исходного Excel, антивируса или Python на компьютере**. Ошибка в предыдущем комплекте EXE: программа подгружала устаревший `.py` по физическому пути, хотя PyInstaller хранит Python-модули внутри архива.

**Исправление внесено в рабочую ветку:** формулы металлозавалки перенесены в `core/melting/metal_balance.py`, вместо загрузки файлов по пути используются обычные импорты. Автоматический тест собранного EXE теперь **импортирует и создаёт главное окно PySide6**, а не ограничивается проверкой наличия JSON.

Что сделать:
1. Откройте **Actions** → **Build Windows EXE (PySide6)** на ветке `engineering-audit-batch-planning-20261028`.
2. Выберите **последний запуск со статусом Success после этой правки**. Старый успешный запуск не обязательно содержит исправление.
3. Скачайте артефакт `LiteynyiTsehPRO-Windows-x64`.
4. Распакуйте архив **в новую пустую папку** (например, `F:\\FoundryPRO`). **Не объединяйте его со старой папкой `_internal`**.
5. Откройте `LiteynyiTsehPRO.exe`. При возникновении новой ошибки приложите скриншот и имя сборки GitHub Actions.

Если новая сборка не получила статус Success, считайте релиз неподтверждённым. На рабочем компьютере отдельно проверьте открытие окна и оба контрольных Excel.

## 5. Другие ошибки

- **Python 3.12 x64 not found:** скачайте Python с https://www.python.org/downloads/windows/ или установите через `winget`, перезапустите командную строку.
- **Tests failed:** скрипт **не создаст распространяемую сборку** с неуспешными тестами. Посмотрите сообщение и тесты, а не обходите проверку вручную.
- **Ошибка при упаковке в ZIP:** проверьте свободное место и права на запись в папку проекта. Собранная папка, возможно, уже находится в `%TEMP%\FPRO\dist\LiteynyiTsehPRO`.
- **Недостаточно места на C:** задайте `FOUNDRY_BUILD_HOME=F:\FPRO` как в варианте C. Окружение и сборка могут занимать много места.
- **Антивирус:** изучите журнал и происхождение файлов; не отключайте защиту системы ради сборки.
- **Не открывается EXE:** проверьте, что скопировали всю папку и что использована Windows x64; откройте ошибку в командной строке или журнале событий Windows.

## 6. Первое использование и безопасность исходных данных

На первом запуске приложение однократно предлагает экскурсию по вкладкам. Повторный запуск обучения — через **«❓ Руководство»**. Пользовательские настройки, включая флаг первого показа, размещаются в `%APPDATA%\LiteynyiTsehPRO`, а не внутри `Program Files`.

Приложение вычисляет **предварительный** проект литейного цеха. Успешные тесты, упаковка PyInstaller и проверка Qt без отображения окна на GitHub runner **не доказывают** инженерную правильность проектирования и не заменяют проверку фактического запуска на Windows с рабочим столом.

В сборку включены также оба проверочных файла `examples/Диплом_1_ведомость_формовки.xlsx` и `examples/Диплом_2_ведомость_формовки.xlsx`. Их можно сохранить из «❓ Руководство» и импортировать для ручной проверки без интернета. Исходные значения дипломов сохраняются на листе «Ведомость формовки»; исправления показаны на листе «Сверка».
