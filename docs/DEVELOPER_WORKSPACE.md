Актуально для ветки `engineering-audit-batch-planning-20261028`.

## Исправленный конфликт плавильных модулей

Исторически существовал `core/melting.py`, но позже появился пакет с тем же именем `core/melting/`. Старый `core/melting/charge.py` пытался вручную прочитать `core/melting.py` с диска через `spec_from_file_location`. В сборке PyInstaller `.py` не обязан существовать как физический файл — поэтому EXE аварийно завершался.

Теперь файл `core/melting/metal_balance.py` содержит неизменённые проверенные формулы и загружается через обычный `from .metal_balance import ...`. Конфликтующий `core/melting.py` удалён. Внешний API `from core.melting import calc_metal_charge` сохранён.

## Что убрано

- Из Git удалены закоммиченные бинарные `.pyc` и устаревшие `__pycache__`, но Python создаёт их локально снова при запуске; они игнорируются Git.
- Оставлены по одной идентичной копии методички и первого диплома. **Оригиналы PDF теперь в `references/`**; они доступны для аудита, но не увеличивают размер переносного EXE.
- Удалены пустые заготовки без реализации (несуществующие экспортеры PDF/DOCX, пустые виджеты, дублирующий `build.bat` и т. п.). Рабочий `build_windows.bat` сохранён.
- Пользовательские настройки `user_data/` **не удалены**: это потенциально ценные локальные изменения. Новые настройки не должны коммититься, путь включён в `.gitignore`. Ранее добавленные в историю файлы пока оставлены; переносить их можно лишь с отдельным сохранением/миграцией.
- Пустые служебные `__init__.py` оставлены — это маркеры Python-пакетов, а не мусор.

## Где хранить новые материалы

- **Новые расчёты и модели** — `core/<department>/`, с тестами в `tests/`.
- **UI** — `gui/tabs/`, `gui/widgets/` или `gui/dialogs/`.
- **Проверенные паспорта** — `data/equipment/`; непроверенные числа нельзя помечать как паспортные.
- **Дипломы и методички в PDF** — `references/`; в комплект Windows не включать без отдельной необходимости.
- **Учебные и тестовые XLSX** — `examples/`, проверка через `import_export/excel_importer.py`.
- **Инструкции** — `docs/`; размещение `README.md` и инструкции сборки в корне допускается.
- **Непубличные настройки и проекты пользователя** — вне репозитория, в папке профиля `%APPDATA%\LiteynyiTsehPRO`.

## Контроль качества

```powershell
python -m pytest -q --timeout=25
```

Windows-сборка вызывается **тем же** `build_windows.bat`, что и у пользователя. CI не ограничивается проверкой существования данных: упакованный EXE в `FOUNDRY_SMOKE_TEST=1` импортирует все вкладки, формулы металлозавалки и создаёт `MainWindow` без показа окна. Ошибки записываются в лог. После успеха необходим отдельный **интерактивный** тест на реальном Windows-десктопе.

## Что ещё требует отдельной проверки

Наличие незаполненных или неподтверждённых справочников и сохранение/загрузка целого проекта не следует считать решёнными задачами. Автоматические тесты проверяют код, но не подтверждают достоверность исходных паспортных характеристик.
