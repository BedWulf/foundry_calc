## Первичная проверка арифметики

Формула металлозавалки:
`M = G * (1 + L/100 + B/100) / (1 - U/100)`.
Она корректна **только для задокументированных оснований процентов**: `L` и `B` относительно годного `G`, `U` относительно завалки.

- Контроль 1: `(37000 + 16320 + 2666) / 0.95 = 58932.6315789` т. В контрольном дипломе указано **58 932 т**; это расхождение округления/представления, а не точное тождество.
- Контроль 2: `(64000 + 22400 + 4320) / 0.95 = 95494.7368421` т. Контрольное число **95 494 т** также не совпадает с точным результатом.
- Поэтому тесты должны проверять точную формулу отдельно от округлённых чисел дипломов. Не корректировать формулу под печатную цифру.

## Очередность работ

1. Ввести для справочников метаданные происхождения: `source_document`, `source_page`, `source_type` (`manufacturer_passport` / `standard` / `textbook` / `diploma_example` / `assumption`), `verification_status` и `verified_at`. Отсутствие первоисточника обозначать явно.
2. Добавить автоматическую проверку диапазонов, размерностей, уникальности ID и полноты критичных характеристик; не выдавать неподтверждённые данные за паспортные.
3. Создать тесты сохранения баланса металла, граничных процентов, округления форм и запрета двойного учёта брака.
4. Сверять оборудование с заводскими паспортами и действующими техническими документами, документируя расхождения без бездоказательной замены значений.
5. Расширить аудит на плавку, стержневое, смеси, очистку, склады, транспорт, фонды времени, персонал и площади.

**Статус этапа:** выявлены конкретные недостатки прослеживаемости и математические контрольные расхождения округления. Полная паспортизация каталога, прогон тестов и аудит остальных разделов ещё не выполнены.

### Несогласованности, требующие инженерной проверки

- `core_machines.json` / `ZB08Y-80`: цикл 40 с, 8 гнёзд дают теоретически `3600/40×8 = 720` стержней/ч; в справочнике указано `576` стержней/ч. Возможное объяснение — эффективный коэффициент 0,8, но он **не документирован**; нельзя заменять 576 на 720 без подтверждения реальной производительности.
- `mixers.json` / `Ohl-11311`: описание обещает охлаждение до 30–40 °C, в `specs.outlet_temp_c` стоит 50 °C. Неясно, относится ли число к другому режиму; требуется паспорт и подтверждение.
- `furnaces.json`: отсутствуют индивидуальные подтверждённые ссылки на паспорта для параметров печей. `capacity_t / melt_time_h` не обязательно равняется `productivity_t_h`: технология, непрерывная подпитка, полезное время и условия испытаний могут различаться. Если указанная производительность превышает эту простую оценку, валидатор выдаёт повод для проверки, а не автоматически отвергает печь.

**Ограничения:** новые проверки пока автономны и не интегрированы в GUI. Полный прогон pytest и сверка паспортов не выполнены; программная валидность не равнозначна достоверности источников.
