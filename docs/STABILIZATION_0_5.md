# Контрольная точка 0.5: стабилизация (30.10.2026)

Документ описывает состояние **кандидата**, а не подтверждённый промышленный релиз.
Исходная рабочая версия: `engineering-audit-batch-planning-20261028`,
коммит `15872356` (`0.4.0-stage4`).

## Подтверждённая база

- Автосохранение и восстановление после сбоя: версия 0.4.0-stage4,
  217 тестов и 2 подтеста пройдены в Linux- и Windows-GitHub Actions.
- Windows EXE создан и прошёл служебное открытие главного окна внутри
  упакованного приложения (GitHub Actions Windows run 41066350608).
  Это **не** проверка всех пользовательских действий на реальном экране.
- Импорт и контроль двух дипломных Excel, отдельное сохранение целого
  `*.fpro.json`, смешанный ручной и автоматический формовочный парк,
  сводка мощностей и пиковый сценарий смены реализованы.

## Новые возможности кандидата

1. История предыдущих сохранённых редакций проекта:
   `core/version_history.py`, окно в меню «Файл», открытие старой
   редакции только как несохранённой копии. Отдельно от `recovery/`.
2. Защита сравнения единиц смесеприготовления и запрет условного расчёта
   персонала при ошибке формовочного планирования.
3. Однократное применение глобального Qt-оформления для последовательных
   окон, без многократной дорогостоящей перерисовки всех виджетов.

Новые функции считаются **кандидатами** до прохождения объединённых тестов
и контрольного Windows-сценария.

## Обязательные проверки до 0.5

- [ ] Объединённый набор `python -m pytest -q --timeout=25` проходит
      без зависаний.
- [ ] Windows `build_windows.bat` создаёт EXE и smoke test проходит.
- [ ] Реальный запуск EXE на Windows: меню, тёмная тема, большие окна
      таблицы и выбора оборудования.
- [ ] Первый диплом: импорт → ручной парк → `Ctrl+S` →
      повторное сохранение → предыдущая версия в истории.
- [ ] Восстановление старой версии открывает копию; исходный файл
      и самая новая редакция не изменяются.
- [ ] Второй диплом создаёт независимую историю; аварийные снимки
      двух проектов не смешиваются.
- [ ] После сбоя окно восстановления сохраняет номенклатуру,
      оборудование и настройки, а внешний изменённый файл не затирается.
- [ ] Повреждённые и конфликтные пользовательские справочники
      не подменяются молча.
- [ ] Проверен экспорт сводки и листа баланса мощностей в Excel.

## Что не следует выдавать за готовую инженерную систему

- Источники паспортных характеристик всех машин требуют независимой
  проверки, как и методические коэффициенты численности работников.
- Годовой баланс и сценарный сменный пик не составляют посменный
  календарь выплавки, подготовки смеси, изготовления стержней и формовки.
- Не реализован полный техническо-экономический оптимизатор с жизненным
  циклом оборудования, резервами, простоями и логистикой.
- Нет утверждённой геометрической планировки оборудования по зданию.
- Не подготовлено формальное подтверждение применения в реальном
  промышленном проектировании.

## Порядок следующих инженерных работ

1. Ведомость формул и коэффициентов с ссылками на первоисточники,
   размерностями, диапазонами и независимыми тестовыми примерами.
2. Согласованный календарь партий, плавок, стержней, смеси и ковшей,
   включая буферы, простои и реальные смены.
3. Сравнение нескольких допустимых комплектов оборудования по
   капитальным и эксплуатационным затратам.
4. Проектировка площадей и транспорта на основе проверенной
   производственной модели.

Этот документ заменяет устаревшие статусы ранних этапов аудита,
но не удаляет их из истории Git.
