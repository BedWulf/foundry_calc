# История сохранённых версий проекта

История версий дополняет, но **не заменяет** автосохранение аварийных копий.
Автосохранение в `recovery/` предназначено для несохранённых данных после сбоя.
История в `history/` сохраняет **предыдущее содержимое файла** перед его
следующим ручным сохранением (`Ctrl+S` или «Сохранить как…» с заменой файла).

## Как пользоваться

1. Создайте проект и сохраните его через «Файл → Сохранить проект как…».
2. Измените номенклатуру или число формовочных линий и снова нажмите `Ctrl+S`.
   Предыдущее состояние файла будет сохранено отдельно, затем обновится
   основной `*.fpro.json`.
3. Откройте «Файл → История версий проекта…» и выберите нужную дату.
4. Нажмите «Открыть копию версии». Будет загружено **несохранённое состояние**,
   и исходный файл останется нетронутым.
5. Чтобы сохранить восстановленную версию, воспользуйтесь
   «Сохранить как…» и укажите новый файл. Обычный `Ctrl+S` также
   предложит выбрать файл, поскольку восстановленная копия не привязана
   к исходному пути.

Перед заменой уже открытого проекта с несохранёнными правками программа
предложит сохранить изменения, отказаться от них или отменить действие.
Внутри версии сохраняются исходные данные, отливки, принятый парк,
выбор оборудования и пользовательские справочники; расчёты пересчитываются
при открытии, как и для обычного проекта.

## Где находятся версии

На Windows: `%APPDATA%\LiteynyiTsehPRO\history\<хеш-пути-файла>\`.

Каждая версия представляет собой полноценный JSON-файл проекта. Для двух
файлов диплома с разными путями создаются отдельные истории, даже если
их внутренние ID совпадают. При переносе проекта по другому пути прежняя
история не появляется автоматически: она остаётся в папке, связанной со
старым абсолютным путём.

До **первого повторного ручного сохранения** история пуста. Версии не
удаляются автоматически — место на диске будет постепенно расходоваться.
Для важных проектов дополнительно храните копии файлов на другом диске.
Не удаляйте каталог `history` без собственной резервной копии.

## Защита данных и ограничения

- Предыдущая редакция проверяется и копируется **до перезаписи** основного
  файла. Ошибка чтения исходного файла, повреждённый JSON или ошибка записи
  в историю отменяют обычное сохранение; рекомендуется «Сохранить как…».
- Повреждённые версии не предлагаются в списке, но не удаляются автоматически.
- Загрузка версии не изменяет файл, из которого она была получена.
- Эта функция не является системой контроля версий Git, не объединяет правки,
  не сохраняет каждую клавишу и не гарантирует сохранность при поломке диска.
- Для истории используются пути файлов, а не только названия проектов,
  поэтому переименование/перемещение файла может разорвать связь с историей.
- Пользовательские справочники при открытии проверяются на конфликты с
  локальными; конфликт не должен скрытно перезаписать карточку оборудования.
- История **не заменяет** проверку инженерных расчётов, паспортов и нормативов.

## Ручная проверка

На учебной копии диплома сохраните первую редакцию, измените парк линий,
повторно сохраните файл, затем откройте историю и выберите старую версию.
Убедитесь, что в окне отображены прежние количества, а исходный файл
по-прежнему содержит новые значения. Сохраните открытую старую редакцию
под новым именем и проверьте оба файла.
