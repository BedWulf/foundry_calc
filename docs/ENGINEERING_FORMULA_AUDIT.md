# Инженерный аудит формул: реестр и проверенные числовые инварианты

Дата: 30.10.2026. Начальный этап независимой проверки математики
«ЛитейныйЦех PRO», кандидат следующего инженерного обновления.

**Граница аудита:** здесь проверены арифметика, размерности и
допустимые диапазоны некоторых операций по опубликованному коду. Записи
«по методичке» и «по диплому» в исходных файлах обозначают заявленные
авторами источники, но **не означают, что весь оригинальный PDF был
независимо сверен в рамках этого этапа**. Паспорта оборудования ещё
не подтверждены по оригиналам.

## Реестр основных формул и границ

| Модуль | Формула/сопоставление | Единицы и база | Статус |
|---|---|---|---|
| `core/melting/metal_balance.py` | `M = G × (1 + L/100 + B/100) / (1 − U/100)` | G и M — т/год, L и B — % **от годного G**, U — % от завалки | Алгебра проверена; внешняя методическая трактовка процентов остаётся предметом сверки |
| `core/melting/furnace_calc.py` | `P' = M × k / (F × q)`; `N = ceil(P'/K_max)` | M — т/год; F — ч/год; q — т/ч; N — шт | Размерность согласована, паспортные q и коэффициенты проверить |
| `core/molding_batch_planner.py` | Годовое распределение форм с переналадками и совместимостью | формы/год, часы/линию | Проверки программы есть; это не график смен |
| `core/core_making.py` | `N_core = ceil(N_molds × cores_per_mold)`; `q = 3600/cycle × cavities` | стержни/год, стержни/ч | Арифметика описана в коде; достоверность среднего числа стержней требует номенклатуры |
| `core/sand_prep.py` | `V_loose = V_tamped × rho_tamped / rho_loose` | м³/год и т/м³ | Размерность согласована; плотности/объёмы зависят от материала и геометрии |
| `core/plant_capacity.py` | `потребность ≤ принятая мощность` для каждого физического потока | не смешивать т, м³, формы, стержни | Присутствует проверка несогласованных единиц; неизвестное не равно нулю |
| `core/shift_capacity.py` | Пиковые расходы × длительность смены против сменных ресурсов | т/смену, стержни/смену | Сценарная оценка, **не** подтверждённый производственный календарь |
| `core/time_funds.py` | `F_nom = (365 − weekends − holidays) × 24` | ч/год | Нужна сверка календарных допущений для всех режимов |
| `core/workforce.py` | Укрупнённые нормы численности | человек, смена, ремонтные единицы | Некоторые нормы откалиброваны по диплому; универсальность не подтверждена |

## Обнаруженные и исправленные несогласованности баланса металла

1. При G = 37 000 т/год, L = 28.9 %, B = 5 %, U = 5 %:
   `M = 37000 × 1.339 / 0.95 = 52 150.526… т/год`.
   Ранее комментарий ошибочно обещал около 58 721 т при этих
   настройках. Исправлено **пояснение**, уравнение не менялось.
2. В контрольном примере отдельно заданы G = 37 000 т,
   L = 16 320 т, B = 2 666 т, U = 5 %. По ним
   `M = (37000 + 16320 + 2666)/0.95 = 58 932.632… т/год`.
   Программа тестирует именно эти исходные числа, а не процентный
   набор по умолчанию. Числа источника указаны в коде; сверка
   непосредственно по листам PDF остаётся отдельной задачей.
3. Прежнее значение `REFERENCE_YIELD=0.611` не равно
   `37000/58932≈0.6278423`. Константа исправлена как
   **арифметическое отношение обозначенных в коде масс**;
   это не введение новой нормативной величины.
4. Входы металлозавалки теперь обязаны быть конечными числами:
   `G≥0, L≥0, B≥0, 0≤U<100`. Проверка выполняется и при
   нулевом выпуске. Отрицательный процент не может уменьшить
   потребность в завалке незаметно.
5. Файл проекта `*.fpro.json` с отрицательными процентами или
   угаром 100 % отклоняется **до** создания/обновления GUI;
   не допускается перезапись последней корректной версии
   из-за ошибки входных данных.

## Вопросы следующей проверки, которые нельзя замолчать

- При 249 днях и 24 часах/сутки nominal = 5976 ч/год,
  но табличный фонд оборудования для трёх смен указан 7008 ч.
  Эти цифры не согласуются с **одним и тем же календарём**;
  необходимо проверить, не взяты ли они из разных режимов
  (непрерывное производство / другой календарь). Пока
  автоматически менять табличный фонд **нельзя**.
- `calc_sand_volumes` использует плотность стали для объёма
  металла в форме. Для алюминия и чугуна нужна проверка
  фактически применяемой плотности и передачи её из проекта.
- Для смесеприготовления нужно подтвердить плотности и
  коэффициенты регенерации по первоисточникам.
- Для штатной численности нужно отделить методические нормы
  от коэффициентов, подобранных для совпадения с дипломом.
- Потребны независимые случаи с другим материалом, иной
  сменностью, крайними габаритами опок, несовместимыми
  формовочными линиями и недостаточной мощностью печей.
- После сверки оригинальных PDF составить постраничную ведомость
  «уравнение — лист источника — входные данные — результат —
  допустимая погрешность», не перенося случайные цифры диплома
  в универсальные нормативы.

## Тестирование

`tests/test_metal_balance_validation.py`: эталонная алгебра,
контроль исходных чисел, крайние/некорректные параметры, отказ
сохранения при недопустимых процентах и сохранение старого файла.
Существующие эталонные тесты `tests/test_melting.py` должны
сохранять прежние результаты для корректных входов.

Этот реестр нужен для поэтапной проверки инженерной модели,
а не для преждевременного утверждения готовности цеха.
