# Автосохранение и восстановление после сбоя

Автовосстановление не заменяет **Ctrl+S**. Оно защищает от потери последних несохранённых данных при сбое приложения или внезапном отключении питания, насколько это позволяет уже созданный снимок. Обычный `*.fpro.json` никогда не перезаписывается фоновым сохранением.

## Как работает

1. После изменения данных программа запускает таймер: при отсутствии новых правок примерно **12 секунд** создаёт резервную копию. Дополнительная проверка выполняется каждые **60 секунд** и охватывает изменения, которые не вызвали отдельного сигнала интерфейса.
2. Копия сохраняет полную номенклатуру, парк формовочных линий, исходные настройки, выбранное оборудование и доступные пользовательские каталоги. Расчётные итоги вычисляются заново при восстановлении.
3. Для каждой открытой редакторской сессии используется отдельный идентификатор. Диплом №1 и диплом №2 не перезаписывают резервные снимки друг друга.
4. В собранном Windows EXE резервные файлы находятся в `%APPDATA%\LiteynyiTsehPRO\recovery\` с именами `recovery-<uuid>.fpro.json`. **Не удаляйте папку**, если ещё хотите восстановить работу.
5. При нормальном сохранении проекта его текущая аварийная копия удаляется. При обычном закрытии после выбора «Не сохранять» текущая копия также удаляется. При выборе «Отмена» закрытие отменяется, данные остаются открытыми.

Автосохранение **не** создаёт новые версии основного файла и не заменяет ручную резервную копию на отдельном диске.

## После сбоя

При следующем интерактивном запуске, если остались действительные аварийные снимки, откроется окно **«Восстановление несохранённой работы»**. В нём показаны название проекта, время создания копии, число отливок и путь к исходному файлу.

- **Восстановить** — открыть выбранный снимок, сохранив исходный `*.fpro.json` без изменений. В заголовке будет `*` — это несохранённая восстановленная версия.
- **Позже** — закрыть окно без удаления копий. Вернуться к ним можно через **«Файл» → «Восстановить несохранённую работу…»**.
- **Удалить выбранную копию** — отдельное действие с подтверждением. Оно удаляет только аварийный снимок, а не обычный проект.

Если после создания снимка исходный `*.fpro.json` был изменён или перемещён, восстановленная работа открывается **без пути для обычного сохранения**. Используйте **«Сохранить как…»**, чтобы избежать затирания более новой версии исходного документа.

Если копия оказалась повреждена, она не предлагается к восстановлению, но остаётся в папке для ручной диагностики. При повреждении пользовательского каталога программа старается сохранить хотя бы основную номенклатуру и проект, не подменяя этот каталог.

## Ограничения

- Изменения за секунды **до первого успешного автосохранения** могут не попасть в аварийную копию. В случае полного отказа накопителя не гарантируется сохранность данных.
- При нормальном закрытии с осознанным отказом от сохранения аварийная копия **не сохраняется как тайный черновик**.
- Снимки, оставленные через «Позже», сохраняются и могут занимать место. Программа не удаляет их автоматически. Лишние удаляются из окна восстановления или вручную после резервного копирования.
- При обнаружении на компьютере стороннего файла с конфликтующим ID пользовательского оборудования его не подменяют молча. Конфликт обрабатывается по правилам открытия основного проекта.
- Наличие снимка не делает инженерный расчёт нормативно проверенным.

## Ручная проверка

1. Откройте первый диплом, измените число формовочных линий и импортируйте исходную номенклатуру. Подождите не менее 15 секунд после последней правки.
2. Убедитесь, что в `%APPDATA%\LiteynyiTsehPRO\recovery\` появился снимок, а исходный `*.fpro.json` остался неизменным.
3. Для имитации аварийного завершения **только на тестовом проекте** завершите процесс через диспетчер задач, не используя «Файл» → «Сохранить» или штатное закрытие.
4. Запустите EXE и нажмите «Восстановить». Проверьте номенклатуру, ручной парк, число партий, переналадки и наличие `*` в заголовке. Обычный файл не должен быть автоматически перезаписан.
5. Попробуйте «Позже», затем пункт меню «Файл» → «Восстановить…». Проверьте, что копии остались.
6. После успешного ручного сохранения проверьте исчезновение **текущего** аварийного снимка.
7. Повторите сценарий для второго диплома. Снимки двух проектов не должны смешиваться.

Не проверяйте аварийное восстановление на единственной копии важного дипломного проекта.
