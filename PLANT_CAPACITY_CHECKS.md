# Сквозная проверка производительности цеха (этап 5)

## Назначение
Модуль `core/plant_capacity.py` сравнивает **годовые** потребности и принятую номинальную производительность оборудования по **одинаковым физическим потокам**. Вкладка «Сводка» содержит отдельную ведомость «Баланс мощностей и узкие места», а Excel-экспорт создаёт лист «Баланс мощностей».

Статусы:
- `ok`: потребность не превышает оценочную годовую производительность;
- `deficit`: потребность больше доступного годового объёма; сводка помечается неполной;
- `unknown`: нельзя сделать вывод из входных данных. **Ноль нельзя подставлять вместо неизвестного показателя.**

## Проверяемые позиции
1. **Формовочное**: требуемые формы/год против распределённых между совместимыми линиями. В распределении уже учтены опоки, металл на форму, материал, эффективный фонд и заданные переналадки.
2. **Плавильное**: масса *металлозавалки* (т/год) сравнивается с паспортными т/ч × числом принятых печей × фондом. Не путать металлозавалку с массой жидкого металла после угара и годным выпуском.
3. **Стержневое**: стержни/год против паспортных стержней/ч × число машин × фонд.
4. **Смесеприготовление**: каждая операция сравнивается **отдельно**: формовочная/стержневая смесь и просеивание — м³/год, дробление комьев — т/год. Неизвестные или несовместимые единицы дают статус `unknown`, а не ложное сравнение.
5. **Ковши**: требуемые тонны жидкого металла в год против числа *рабочих* ковшей × вместимость × фонд/цикл. Резервные и ремонтные ковши не засчитываются как постоянно работающие.
6. **Краны и внутрисменная синхронизация**: всегда `unknown`, пока нет тактовых и маршрутных характеристик.

## Принципиальные ограничения
- Успешный годовой баланс **не доказывает**, что в одной смене хватает расплавленного металла, смеси, стержней и ковшей для реально работающих линий. Нужны календарные планы партий, длительности плавки/заливки, буферные запасы и логистика.
- Паспорта оборудования в проекте требуют проверки. Коэффициенты технической готовности и резерва не добавляются скрыто; все значения должны быть обоснованными.
- Данные отдельных отделений наследуют методические расчёты прежнего проекта; этот этап **не заменяет** независимую верификацию каждой формулы.
- Взаимозависимый автоматический подбор оборудования по стоимости владения пока не реализован. Текущие сравнения — проверка ограничений, а не глобальная оптимизация.
- Если нет полной номенклатуры, баланс формовки остаётся `unknown`; другие отделения могут отражать только предварительную оценку.
- Число форм не изменяется при ручном увеличении числа линий. Дополнительные линии создают потенциальный резерв мощности, а не новую производственную программу.

## Запуск проверки
`python -m pytest -q tests/test_plant_capacity.py`

Все изменения в рабочей ветке проходят GitHub Actions `Calculation checks` и `Build Windows EXE (PySide6)`. Скачать готовый пакет можно только после успешного задания; проверка безэкранного запуска не заменяет открытие окна на настоящей Windows.
